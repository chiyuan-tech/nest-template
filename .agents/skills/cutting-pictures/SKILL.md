# For cutting pictures 忠实还原规则

## 1. 设计稿是唯一视觉基准

必须将用户指定的原始设计稿作为唯一视觉目标，不得擅自重新设计、简化或改变设计语言。

开始编码前，必须分析并记录：

- 原始画布宽高和宽高比
- 页面内容最大宽度
- 每个主要模块的边界
- 元素之间的水平和垂直间距
- 字号、行高和字重
- 圆角、边框、阴影和颜色
- 图片裁切比例和视觉焦点
- 元素的对齐基准
- 桌面端与移动端的布局变化

禁止依靠大致目测直接开始编码。

## 2. 先进行视觉元素分类

将设计稿中的所有内容分为：

1. HTML 文字
2. UI 控件
3. 图标
4. 内容图片
5. 装饰图片
6. 背景纹理

分类完成后才能开始切图和编码。

## 3. 文字处理规则

所有网页界面文字必须使用真实 HTML 文字实现，包括：

- 页面标题
- 描述
- 导航
- 按钮文字
- 输入框文字
- Tab 标签
- 参数选项
- 卡片标题
- 时间和数字
- 功能名称
- 辅助说明

禁止把这些文字保留在背景图或切图中。

禁止在图片里保留一份文字后，再使用 HTML 覆盖一份相同文字。

如果发现图片中包含需要由 HTML 实现的文字，必须：

1. 重新裁切不含文字的图片；
2. 或使用图像编辑/生成工具移除文字并修复背景；
3. 不得通过覆盖色块、模糊或重复文字掩盖。

唯一例外：文字确实属于真实图像内容，例如路牌、海报、包装或场景招牌。此类文字属于图片本身，不需要用 HTML 重建。

## 4. 图片切图规则

图片只保留无法合理通过 HTML/CSS 重建的视觉内容，例如：

- 人物
- 产品照片
- 视频画面
- 摄影场景
- 复杂插画
- 真实纹理
- 复杂光影
- 时间轴中的真实帧画面

每张图片必须：

- 按实际使用区域单独输出；
- 不包含网页标题、按钮、标签和 UI 控件；
- 保持原始视觉焦点；
- 使用正确的宽高比；
- 提供明确的 object-position；
- 避免同一张大图承担多个独立 UI 区域；
- 优先使用 WebP 或 AVIF；
- 不得拉伸变形。

## 5. UI 元素必须使用代码实现

以下内容必须使用 HTML/CSS/React 实现：

- 面板
- 卡片
- 输入框
- 按钮
- Tab
- Select
- Toggle
- 分割线
- 边框
- 渐变
- 阴影
- 进度条
- 时间轴结构
- 播放控件
- Hover、Focus、Selected、Disabled 状态

禁止将整个设计稿或完整模块裁成一张图片放到页面中。

## 6. 禁止使用低质量 CSS 绘画代替图片

如果设计稿中是人物、汽车、城市、山脉、电影画面或真实摄影素材，必须使用真实图片资产。

禁止使用以下方式代替：

- div 拼接汽车
- CSS 几何图形模拟人物
- 渐变色块代替视频画面
- 简单矩形代替照片缩略图
- CSS 图形代替复杂插画
- Emoji 代替正式图标

普通界面图标使用与设计风格匹配的图标库，不得随意使用字符或 Emoji。

## 7. 布局测量规则

在实现前记录主要元素在原图中的相对位置：

- 左侧内容区宽度
- 右侧工作台宽度
- 两列之间距离
- Hero 顶部和底部留白
- 标题宽度和换行位置
- CTA 尺寸和间距
- 工作台内部左右列比例
- 视频预览比例
- 底部卖点栏高度和分隔距离

优先使用 Grid 和 Flex 实现结构。

禁止通过大量无依据的 absolute、top、left 和负 margin 强行拼接页面。

绝对定位只用于明确的装饰元素或局部叠层。

## 8. 字体匹配规则

必须识别并选择最接近设计稿的字体。

对照检查：

- 字体家族
- 字重
- 字号
- 行高
- 字间距
- 标题换行位置
- 数字宽度
- 按钮文字大小

不得仅通过放大或缩小整个容器来模拟字体差异。

## 9. 同尺寸视觉复查

实现完成后，必须使用与原图完全相同的视口尺寸进行截图。

对比时必须保证：

- 相同视口宽高
- 相同页面缩放比例
- 相同滚动位置
- 相同交互状态
- 字体已经加载完成
- 图片已经加载完成
- 动画处于稳定状态

禁止使用不同宽高比的截图进行视觉判断。

## 10. 必须进行二次修复

第一次实现完成不代表任务完成。

必须执行以下流程：

1. 启动真实页面；
2. 使用原图尺寸截图；
3. 同时打开原图和实现截图；
4. 逐项对比布局、比例、字体、图片、颜色和间距；
5. 输出问题清单；
6. 修复所有 P0、P1 和 P2 问题；
7. 重新截图；
8. 再次对比；
9. 确认通过后才能结束任务。

不得只以 build 成功、页面可打开或组件已完成作为验收标准。

## 11. 还原优先级

按以下顺序进行修复：

1. 页面整体比例和布局
2. 主要模块位置与大小
3. 图片内容和裁切
4. 标题字号与换行
5. 间距和对齐
6. 颜色、边框、圆角和阴影
7. 图标和细节
8. 动画和交互

整体布局不正确时，不要先处理阴影和小图标。

## 12. 完成标准

只有满足以下要求才可以声明完成：

- 页面整体结构与原图一致；
- 主要模块位置和比例一致；
- 没有图片文字与 HTML 文字重叠；
- 没有使用 CSS 色块代替真实图片；
- 所有图片宽高比正确；
- 标题换行与原图接近；
- 桌面端同尺寸截图对比通过；
- 移动端没有横向滚动和内容裁切；
- 核心交互可以使用；
- 控制台没有错误；
- 项目可以正常构建；
- 已完成至少一次截图对比和修复。

## Image to Code Prompt

使用image to code 命令时候，也追加这个 For cutting pictures命令，并且prompt改为：

请使用 Image to Code 忠实还原我提供的设计稿。

开始编码前不要立即写代码，先完成以下工作：

第一步：识别原图的准确宽高比、主要布局、模块边界、字体层级、间距和图片区域。

第二步：输出资产清单，将每个元素标记为以下类型之一：

- HTML 文字
- UI 控件
- 图标
- 内容图片
- 装饰图片
- 背景纹理

第三步：确定切图方案。

切图必须只保留无法通过 HTML/CSS 合理实现的视觉内容，例如人物、汽车、城市、视频画面、复杂光影和真实纹理。

所有页面标题、描述、按钮文字、导航、Tab、参数、数字、输入框文字、功能名称和辅助说明必须使用 HTML 实现，禁止包含在切图中。

如果原始素材中的网页文字与背景已经合并，必须先移除文字并修复背景，再作为无文字素材使用。禁止保留图片中的文字后再次叠加 HTML 文字。

真实场景中的招牌、海报、包装和路牌文字可以作为图片内容保留。

设计稿中的汽车、人物、摄影棚、城市、参考图和视频帧必须使用真实图片资产。禁止使用 CSS 几何图形、渐变色块、div 拼图或简单插画代替。

UI 面板、输入框、按钮、Tab、Select、Toggle、边框、进度条、时间轴结构和播放器控件必须使用代码实现。

实现时必须保持：

- 原图画布比例
- 两列布局比例
- 元素相对位置
- 标题换行
- 图片裁切焦点
- 字体层级
- 间距
- 圆角
- 边框
- 阴影
- 主题颜色

不要重新设计，不要简化，不要根据自己的审美改变布局。

完成后必须进行视觉复查：

1. 使用与原图完全相同的视口尺寸运行页面；
2. 等待字体、图片和页面状态稳定；
3. 截取实现页面截图；
4. 同时查看原图和实现截图；
5. 对比整体布局、模块尺寸、位置、字体、换行、间距、图片内容、裁切、颜色、边框和阴影；
6. 输出 P0、P1、P2、P3 问题；
7. 自动修复全部 P0、P1 和 P2；
8. 重新截图并再次对比；
9. 至少完成一次“截图—对比—修复—重新截图”循环；
10. 只有主要视觉差异已经解决后才能声明完成。

Build 成功不代表视觉还原完成，必须以最终同尺寸截图对比为验收依据。
